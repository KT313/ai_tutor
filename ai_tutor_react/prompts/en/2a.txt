# Guide for Creating AI Tutor Learning Content

## 1\. Objective

Using the provided documents (e.g. a question catalog and lecture slides), create a single JavaScript variable called `CONTENT_DATA`. This variable serves as a structured knowledge base for an AI-powered learning tutor.

## 2\. Fundamental Principles of Structuring

### A. Semantic Grouping Instead of Linear Sequence

The most important task is to group the content from the documents into a small number of thematically coherent **learning cards**. Do **not** create a separate card for each individual question from the question catalog. Instead, combine logically related topics into a single overarching card.

  * **Examples of good card titles:** "Fundamentals of Parallel Processing", "Processes, Threads & Synchronization", "Swarm Intelligence Algorithms".
  * **Example of a bad structure:** One card for "What is a process?", another for "What is a thread?", a third for "What is the difference?". Instead, combine these into the card "Processes, Threads & Synchronization".

### B. Clear Separation of Keyword, Explanation, and Tutor Knowledge

Each individual content point should be structured according to the following principle to create a clear and interactive learning interface:

1.  **`string` (The Keyword):** This is the visible text. It must be **extremely concise** — ideally one to three words. It serves as an anchor or label for the concept.

      * *Good:* `"Process"`, `"Amdahl's Law"`, `"Advantages"`
      * *Bad:* `"A process is a program in execution with its own isolated memory space."`

2.  **`tooltip` (The Explanation):** This is the "first level" of information that appears on mouse hover. It contains the **short definition, the most important formula, or a concise example list**. Keep the tooltip informative but short. HTML tags like `<strong>` and `<br>` are allowed and encouraged.

3.  **`verbose_tutor_info` (The Tutor Knowledge):** This is the "second level" of information that is **only visible to the AI**. This is where comprehensive explanations, alternative definitions, common misconceptions, examples, and specific instructions for the tutor belong, to enable deep questioning.

### C. Readability of the Learning Card as the Top Priority

The arrangement of `string` elements on the final website must be logical and easy to read.

  * **Lists with Labels:** When a row represents a concept and its sub-items, the first `string` element should serve as a label and end with a **colon**.

      * *Example:* `[{ "string": "Thread Organization Forms:" }, { "string": "Dispatcher/Worker" }, ...]`
      * *Result:* • Thread Organization Forms: **Dispatcher/Worker** **Team** **Pipeline**

  * **Clearly Named Main Topics:** Instead of vague labels like `"Properties:"`, the main concept itself should serve as the label.

      * *Bad:* `Thread Properties:`
      * *Good:* `Thread` (with the properties in the tooltip or `verbose_tutor_info`)

The basic structure remains as in the original guide, but is supplemented by the principles mentioned above.
